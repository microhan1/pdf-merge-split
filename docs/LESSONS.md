# 실수 기록 (LESSONS)

이 저장소에서 실제로 생긴 문제를 적는다. 새 문제가 생기면 같은 형식으로 **해당 절 맨 아래에 추가**하고, 재발 방지 시험이나 규칙을 반드시 함께 남긴다. 요약 규칙은 [CLAUDE.md](../CLAUDE.md)에 있다.

형제 저장소의 기록을 먼저 읽고 처음부터 피하도록 설계했다: `photo-organizer`·`music-tag-filler`·`music-folder-organizer`의 `docs/LESSONS.md`, `scan-pdf-split`의 시험, `TrimPDF/regress`. 그쪽에서 겪은 것 — 시험이 운영 서버를 침(511건), 기본 인자로 묶인 fetch는 모듈 패치로 안 막힘, 작업 스레드가 Tk 객체를 쥐어 `Tcl_AsyncDelete`로 죽음, 설정 파일 타입 하나에 창이 안 뜸, pack 순서로 버튼이 잘림, 4개 언어 중 긴 문구가 최소 크기에서 잘림, 저장소에 settings.json이 생김, cp949 출력 오류, onefile exe의 부모·자식 프로세스, heredoc 백슬래시, 캡처가 잠금 화면을 찍음 — 은 여기서 처음부터 막았다.

형식: 증상 → 원인 → 해결 → 재발 방지

## A. 제품 코드 버그

### A1. 미리보기 그림이 `image "pyimageNN" doesn't exist`로 안 그려짐 (2026-10-15, GUI 시험이 잡음)
- 증상: 시험마다 새 `Tk()`를 만들자 두 번째 창부터 미리보기 캔버스가 `TclError: image "pyimage49" doesn't exist`를 던짐. 첫 창(실제 사용)에서는 안 보임
- 원인: `ImageTk.PhotoImage(img)`가 **처음 만든 Tk(기본 루트)** 에 이미지를 등록한다. 그 루트가 이미 닫혔으면 다른 인터프리터의 캔버스는 그 이미지를 모른다
- 해결: `ImageTk.PhotoImage(img, master=캔버스)`
- 재발 방지: GUI 시험 전체(창을 여러 번 만듦). 규칙 — **PhotoImage는 항상 master=를 준다**

### A2. 새 버전 확인 중 창을 닫아도 App이 풀리지 않음 (2026-10-15, 약한 참조 시험이 잡음)
- 증상: 요청이 나가 있는 동안 창을 닫고 주 스레드에서 `gc.collect()` 해도 `weakref(app)`가 살아 있음. `update_check`는 이미 상자+폴링 구조라 스레드는 App을 쥐지 않았는데도 그랬다
- 원인: 쪽 범위 입력칸의 `var_pages.trace_add("write", lambda: self._on_pages_edit())`. trace 콜백은 **Tcl 명령 표**에 등록되어 GC가 볼 수 없는 참조로 App을 붙잡는다(공통 지시서의 "Tk 변수 trace가 Tcl 쪽에 등록된 앱은 닫기 전에 trace를 풀어야 한다"가 바로 이것)
- 해결: trace 이름을 기억해 두었다가 `_close_when_idle`에서 `destroy` 직전에 `trace_remove`
- 재발 방지: `test_window_is_released_after_closing_during_a_request`(요청 중 닫기 → gc → 약한 참조가 None). 규칙 — **Tk 변수 trace를 걸면 닫을 때 푼다**

### A3. 최소 크기에서 「용량 줄이기」 탭 아래 문구가 잘림 (2026-10-15, 배치 시험이 잡음)
- 증상: 940×620(처음 정한 최소 크기)에서 일본어 압축 탭의 결과 안내(3줄)와 예상 크기 줄이 잘림. 알림 줄이 뜨면 한국어·영어도 2~8px 모자람
- 원인: 가운데 줄(옵션 탭 | 미리보기)만 늘어나는 구조라, 창이 작아지거나 아래에 알림 줄이 끼면 그 줄이 줄어들고 Notebook 페이지가 잘린다. 파일 목록 버튼을 3줄로 쌓아 파일 칸이 155px나 됐고, 일본어 문구는 영어보다 한 줄 더 길었다
- 해결: 버튼을 3열 2줄로, 목록 4줄·기록 3줄, 머리글·아래쪽 여백 축소, 일본어 문구 단축, 최소 높이 700
- 재발 방지: `tests/test_layout.py`(4개 언어 × 두 탭 × 기본·최소 크기 × 알림 유무). 규칙 — **창 크기를 정할 때 가장 긴 언어(일본어·중국어 2줄 문구)로 재고, 알림 줄이 낀 상태도 잰다**

### A4. 굵은 글씨(제목·요약·예상 크기)만 한글이 명조체로 찍힘 (2026-10-15, 캡처를 눈으로 보고 발견)
- 증상: `font=("", 10, "bold")`로 만든 라벨의 한글만 바탕체 같은 글꼴로 나오고, 일반 ttk 라벨은 맑은 고딕. 배치 시험은 모두 통과한 상태
- 원인: 글꼴 가족을 비워 두면 Tk가 굵은 글씨용 가족을 따로 고르고, 그 가족의 한글 대체가 다르다(music-folder-organizer A15와 같은 뿌리)
- 해결: `tkfont.nametofont("TkDefaultFont").actual("family")`로 기본 UI 글꼴 가족을 읽어 `(family, 10, "bold")`로 지정. 굵은 글씨가 1px 커져 최소 크기 일본어 압축 탭이 다시 모자라 여백을 더 줄임(A3)
- 재발 방지: 규칙 — **글꼴 가족을 빈 문자열로 두지 않는다. 캡처는 반드시 눈으로 본다(시험 통과 ≠ 화면 정상)**

### A5. 캡처한 화면에 사용자 이름이 든 경로가 찍힘 (2026-10-15)
- 증상: `done_ko.png`의 기록 줄에 `C:\Users\<이름>\AppData\Local\Temp\...` 경로가 그대로 보임. README에 넣는 공개 이미지
- 원인: 캡처 하네스가 샘플 사본을 `tempfile.mkdtemp()`(사용자 프로필 아래)에 둠. 텍스트 파일의 개인 경로 검사(grep)는 이미지를 못 본다
- 해결: 사본을 저장소의 무시 폴더 `build/shots_*` 아래에 둔다(경로에 이름 없음). 캡처 뒤 지운다
- 재발 방지: 규칙 — **공개 이미지에 찍히는 경로는 저장소 안 무시 폴더로. 캡처를 눈으로 볼 때 경로 줄도 읽는다**

### A6. 같은 이미지를 큰 쪽과 썸네일로 함께 쓰면 큰 쪽이 뭉개짐 (2026-10-15, 사장님 지시로 추가한 엣지 시험이 잡음)
- 증상: 한 이미지가 1쪽에는 전면(약 290 dpi), 2쪽에는 100pt 썸네일로 놓인 PDF를 200 dpi 상한으로 줄이자 이미지가 277px로 줄어 전면 쪽이 흐려짐. 기본 시험 152건은 통과한 상태
- 원인: 배치마다 dpi를 계산해 **최대값**을 썼다. 썸네일은 같은 픽셀을 작은 면적에 놓으므로 dpi가 가장 높게 나오고, 그 값에 상한을 적용하면 가장 많이 줄어든다. 필요한 것은 "가장 큰 배치가 요구하는 픽셀 수"이므로 **최소 dpi**(가장 큰 배치)를 써야 한다
- 해결: `_image_uses`가 배치 중 가장 낮은 dpi를 기억. 전면 배치는 1653px(200 dpi)를 유지
- 재발 방지: `test_one_image_placed_large_and_small_keeps_the_large_placement_sharp`. 규칙 — **"최대/최소"를 고를 때는 그 값이 결과에 어떻게 쓰이는지(픽셀을 더 남기는 쪽이 어느 쪽인지)로 정한다**. 시각 비교 시험(`looks_the_same`)을 모든 색 공간·회전·중첩 경우에 둔다

### A7. 결과 경로를 입력 파일로 주면 원본을 덮어쓸 수 있었음 (2026-10-15, 엣지 시험 설계 중 발견)
- 증상: `-o a.pdf`처럼 입력과 같은 경로를 주면 `.part` 저장 뒤 `os.replace`가 원본을 덮어씀(대소문자·`.\\` 표기 차이도 같은 파일)
- 해결: `pdfops._check_output` — 결과 경로가 입력 중 하나와 같으면(`normcase(abspath)`) `OutputIsInput`, CLI는 번역된 오류와 종료 코드 2, 아무것도 쓰지 않음
- 재발 방지: `test_output_may_not_be_an_input`, CLI `test_output_equal_to_an_input_is_refused`(원본 해시 동일). 규칙 — **사용자가 경로를 지정할 수 있는 모든 쓰기는 입력과 겹치는지 먼저 본다**

## C. 시험 코드 실수

- C1. `widget.cget("state") == "disabled"`가 실패: cget은 `_tkinter.Tcl_Obj`를 돌려줄 때가 있다 → 비교는 `str(cget(...))`
- C2. `Listbox.bbox(i)`가 창이 뜨기 전에는 None → `root.update()` 뒤에 잰다
- C3. 설정 파일 폴더가 없는 임시 경로에 바로 `open(..., "w")` → 시험도 `os.makedirs` 먼저(제품 코드 `save_settings`는 폴더를 만든다)
- C4. 합친 파일의 책갈피 수를 짐작으로 적음(11 ≠ 10) → 기대값은 규칙(파일 항목 1 + 선택한 쪽에 있는 항목)으로 계산해서 쓴다
- C5. 엣지 시험 6건 중 5건이 시험 쪽 잘못이었다: 회전 쪽 크기 기대값 오산, 맑은 고딕에 없는 한자(`\x00`로 추출), PyMuPDF `set_toc`이 거부하는 단계 건너뜀·범위 밖 쪽(→ `get_toc`을 가짜로), 저장 뒤 마지막 진행 호출에서의 취소(파일은 이미 완성) → 실패를 앱 결함으로 단정하기 전에 기대값과 픽스처부터 의심한다(photo-organizer D11). 다만 그 과정에서 진짜 결함 A6·A7이 나왔으니 엣지 시험은 값어치를 했다
- C6. 드롭 이벤트를 흉내 낼 때 백슬래시 경로를 Tcl 리스트에 넣어 `\\p`가 이스케이프로 풀림 → tkdnd는 슬래시 경로를 주므로 시험도 슬래시로

## D. 작업 방식

- D1. 첫 설계에서 형제 저장소의 LESSONS 전체(photo-organizer 18건, music-tag-filler 21건, music-folder-organizer 36건)를 읽고 해당 항목을 코드에 먼저 반영했다. 그래도 A1~A3처럼 **이 프로그램의 구조에서만 나오는 결함**이 셋 있었고 전부 시험이 잡았다 — 시험(특히 배치·약한 참조·여러 Tk)을 처음부터 넣는 것이 교훈을 읽는 것보다 확실하다
